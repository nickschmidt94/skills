# MVP It

Turn an idea or existing product into its smallest responsible sellable form using rapid learning, radical scope control, portfolio distribution, solo maintainability, and lifestyle fit.

When the user explicitly invokes `mvp-it` or asks for “MVP mode,” begin with:

```text
════════════ MVP IT ═══════════════
 Simplify Until It Ships
═══════════════════════════════════
```

For implicit routing, integrate the lens without the banner.

## 1. Choose one mode

An explicit mode supplied by the user wins. Otherwise choose by the decision the user needs:

- **ship** — cut a concrete product or active build to its smallest sellable launch.
- **review** — evaluate an existing product or plan as a sustainable solo business.
- **brainstorm** — generate product directions from a real problem, audience, or portfolio gap.
- **flip** — decide whether to keep, retire, pivot, or sell an existing product.

When requests overlap, choose the mode matching the requested decision rather than the product's lifecycle. State the mode and subject in one line. This step is complete when exactly one mode maps to the user's requested decision.

## 2. Establish the evidence floor

Use the user's topic, conversation, applicable project guidance, and current artifacts. Consult Codex memory only when prior products, audience, or portfolio relationships could change the answer; verify drift-prone facts against current sources when practical.

Classify material inputs as:

- **observed** — verified in a current artifact or source;
- **reported** — supplied by the user but not independently checked;
- **inferred** — reasoned from available evidence;
- **unknown** — missing and capable of changing the recommendation.

Never invent revenue, demand, effort, support load, valuation, build time, distribution, or portfolio connections. If a decisive input is unknown, either give a conditional recommendation that remains useful or ask one concise question when no responsible recommendation is possible.

This step is complete when every input that could materially change the verdict is observed, reported, inferred with its basis, or marked unknown.

## 3. Apply the selected branch

Read exactly one reference:

- SHIP: [references/ship.md](references/ship.md)
- REVIEW: [references/review.md](references/review.md)
- BRAINSTORM: [references/brainstorm.md](references/brainstorm.md)
- FLIP: [references/flip.md](references/flip.md)

Across every branch, test:

- **Sellable value** — the smallest outcome someone would pay for.
- **Subtraction** — what can leave the active scope while preserving value.
- **Learning velocity** — the fastest responsible test of the key uncertainty.
- **Economics** — revenue path, costs, effort, and support burden.
- **Solo shape** — whether one person can operate it alongside other commitments.
- **Flywheel** — whether existing products or audience create genuine distribution, and whether the product contributes back.
- **Public story** — whether sharing useful progress is an appropriate distribution channel, not a requirement.
- **Lifestyle fit** — whether the product supports the user's desired autonomy and obligations.
- **Completion mechanism** — the concrete condition that prevents indefinite building or drift.

Use these as pressure tests, not universal requirements. The user's stated goals, constraints, and product intent take priority.

## 4. Preserve authority

Recommend scope exclusions; preserve existing work unless the user authorizes removal. Treat deletion, publication, deployment, payment setup, outreach, purchases, trades, and product sales as recommendations unless the user separately authorizes execution. Prefer reversible experiments when evidence is weak.

## 5. Deliver the decision

Give a direct but calibrated verdict. Distinguish evidence from assumptions and expose unknowns that limit confidence. Follow the selected reference's output contract without filling unavailable fields with guesses.

End with up to three smallest, evidence-supported next actions. Each action should be executable today and reversible where practical. Obtaining a missing fact is a valid action when that fact could reverse the recommendation.

The response is complete when every branch criterion has been addressed, material unknowns are visible, the verdict follows from the evidence, and suggested actions remain within the user's authority.
